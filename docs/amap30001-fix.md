# 高德 30001 跨城地址解析修复

日期：2026-10-23（北京时间）。这是针对实际失败参数的修复，不是把上游错误改成成功，也没有更换 Key 或生成模拟路线。

## 复现与定位

持久化失败作业中的参数：

```json
{
  "origin": "从无锡市人民医院出发",
  "destination": "118.795193,32.054213",
  "city": "南京市",
  "travel_mode": "driving"
}
```

旧实现把同一个 city 同时用于起终点地理编码；此处它来自南京目的地。实际失败发生在 `v3/geocode/geo` 的起点解析，而非 `v3/direction/driving`。

同一 Key 下的真实请求对照：

| 地址 | city 限制 | 实际结果 |
|---|---|---|
| 从无锡市人民医院出发 | 南京市 | status=0，infocode=30001，ENGINE_RESPONSE_DATA_ERROR |
| 无锡市人民医院 | 南京市 | 同样返回 30001 |
| 无锡市人民医院 | 不传 | status=1，解析成功 |
| 无锡市人民医院 | 无锡市 | status=1，解析成功 |

后两项均解析到 `120.324003,31.542815`。独立调用两组已知坐标的同城和跨城驾车接口也成功。因此本次根因是把目的地城市范围强加给起点；口语包装是需清理的问题，但只删“从/出发”不能解决本次错误。

高德官方将 `300**` 归为服务响应失败，并建议先检查输入参数，不能据此直接断言 Key 失效。参见 [错误码说明](https://lbs.amap.com/api/webservice/guide/tools/info/)。

## 修改内容

- `tools/service.py` 的 `location_query` 分别处理起终点。仅清理完整的“从/由……出发/启程”起点包装，不把“从化市”等地名误删。
- 地址出现明确的“某市”且与 city 提示冲突时，省略冲突限制，让高德解析用户原本给出的地址；同城市或没有明确冲突时保留提示。
- 不新增臆测的当前位置，不把起点替换为默认城市或别的地点。
- 所有直接输入和地理编码返回的坐标均检查经纬度范围，并规范到最多六位小数。依据 [路线参数规范](https://lbs.amap.com/api/webservice/guide/api/direction)。
- 地址多候选仍返回 `requires_clarification`，不直接选择第一条。
- 上游错误回执补充失败接口路径、错误码和错误说明，不携带 Key 或完整带 Key 的 URL。剩余引擎异常允许现有队列有限重试，仍失败则如实报告。

## 验证结果

### 后端回归

76 项通过，1 项默认关闭的 live 集成入口跳过；该入口涉及的真实工具本次另行完整执行。新增 13 项针对地址规范化、起终点城市隔离、六位精度、非法坐标、歧义澄清和剩余上游失败的测试。

证据：[JUnit XML](../data/amap30001-regression-tests.xml)，用例位于 `tests/test_map_routes.py`。

### 真实 MCP 工具

20/20 通过，包括驾车、步行、骑行和原跨城失败参数，不再跳过路线。

原参数得到起点 `120.324003,31.542815`、终点 `118.795193,32.054213`，实际路线距离 `179394 m`、预估耗时 `7806 s`；本轮工具调用约 `269 ms`。这是单次样本，不是平均值或 P95。

证据：[完整工具报告](../data/tool-amap30001-regression.json)。

### 真实模型全链路

向新版 `http://127.0.0.1:8001` 提交“导航到南京市东南大学四牌楼校区”：

1. 模型识别导航意图，缺起点时进入 clarification。
2. 回复“从无锡市人民医院出发”，恢复同一任务。
3. 工具返回真实校区候选，进入 selection，选择“东南大学(四牌楼校区)”。
4. Harness 调用真实 MCP 路线工具，起点不再被南京城市范围限制。
5. 取得有效路线回执，最终任务 completed，并返回路线信息与高德链接。

真实模型为运行配置中的 `grok-4.3`，全流程约 `21.301 s`，包含脚本补充起点与候选选择。路线成功不代表已经启动用户设备上的导航。

证据：[模型导航报告](../data/route-workflow-regression-latest.json)。测试使用独立验收用户，未改动已有用户任务。8001 已重启加载新版代码，8000 旧进程未替换。
