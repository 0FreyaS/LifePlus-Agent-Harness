# LifePlus 学习文档配图说明

## 视觉约定

- 用途：本地 Markdown 学习文档的架构总览，不是上线实测报告或论文结果图。
- 核心信息：独立任务并行，依赖任务等待前序结果；澄清保存状态，用户补充后恢复。
- 内容依据：当前 TaskCoordinator、领域图、Tool Queue、MCP、Memory、Checkpoint 和事件流代码。
- 阅读方向：上方接入与调度，中部并行领域任务，右侧人工恢复与结果呈现，下方工具服务。
- 配色：蓝色编排、绿色工具、橙色人工交互、灰色持久化支撑；文字和箭头也表达语义，不只依靠颜色。
- 未加入内容：BERT、四百个工具、自治 Agent 抢单、实时 GPS、车机控制、生产规模与时延指标。
- 交付：PNG 图片。用户明确选择仅保留图片，不进行 SVG/PDF/PPTX 重建。

## 生成方式与模型边界

使用内置图像生成工具，先生成整体图，再进行两次箭头修订。工具没有返回可验证的具体后端模型名称，因此不能确认或标称使用了 GPT Image 2。未调用其他图像 API，也未使用项目凭证生成图片。

## 结构检查与阅读限制

- 最终图有三个独立领域泳道，不使用天气到地点再到音乐的串行边。
- 顶部协调器连接并行分叉；依赖保存示例单独放在右上。
- 人工交互显示中断、补充、恢复，回路返回原任务。
- MCP 与真实服务之间显示请求/回执双向关系。
- SSE 结果回到用户，不回到规划器重新启动任务。
- 底部保留路线规划、音乐检索、Checkpoint 的能力边界。
- **简化之处：** 所有分支的回执都应分别校验，图片只在右侧抽象展示该职责，不能根据直接连线误认为只有音乐分支有校验。结果回传线并未逐一覆盖所有实际代码路径。
- **简化之处：** 候选选择在查询之后、缺参澄清通常在查询之前，图中合并了部分节点；准确顺序以正文领域子图 Mermaid 为准。
- 图不是逐节点执行记录，也不代表配置的全部可选存储已在本机真实部署。

## 后续修订要求

第一次修订：结果经回执校验、汇总与 SSE 回到用户；MCP/服务双向请求回执；依赖示例不放在所有任务共同主干；增加写操作确认示例；人工恢复回到原任务。

第二次修订：删除领域之间的横向串行箭头；补上协调器到并行分叉的连接；人工恢复回路必须回到澄清/选择节点。最终选用该版本，并在正文明确图示与源码精确执行顺序的区别。
