# 多轮对话与历史记忆

LifePlus 区分“保存过记录”“将记录提供给模型”和“依据执行证据接续任务”。前端显示了历史气泡，不等于模型拥有无限长度的历史。

## 用法

| 交互 | 行为 |
| --- | --- |
| “杭州今天天气怎么样” → “那明天呢？” | 继承同会话的城市，重新查询明天的天气 |
| 出现歌曲/地点候选 → 主输入框输入“第二个” | 匹配唯一、未过期的候选任务，恢复原任务 |
| “明天天气怎么样” → 被问城市 → “杭州” | 从主输入框补充已识别城市，恢复缺参任务 |
| 已选好一个地点 → “骑行过去” | 引用有效且无歧义时，绑定已选坐标重新规划路线 |
| “记住：出行偏好=步行” | 实际写入当前用户的长期偏好 |
| 新建会话 → “我保存的出行偏好是什么？” | 读取同一用户跨会话的长期偏好 |
| “忘记偏好：出行偏好” | 删除偏好，下一轮重新加载，不沿用旧值 |
| “请原样返回我第一次输入的query” | 按当前用户及会话查询第一条输入原文，记录来源证据 |

没有唯一待选择任务、候选过期、序号越界或多个列表均匹配时，主输入框明确提示，请在对应卡片操作。复杂补充、多个待澄清任务及写入确认仍使用绑定 task_id / interrupt_id 的卡片；“好的”不会自动批准写操作。这不是覆盖任意自然语言事件的通用仲裁器。

## 历史与窗口

用户请求和最终答复保存在业务数据库，不依赖前端 localStorage。主输入框提交的候选序号也会记录为会话输入，刷新后保留；相同请求标识的重复提交不会重复恢复或重复显示。

模型默认使用最近 12 条消息、总计 12000 字符，单条最多 2000 字符，同时受上下文有效期限制。MemoryBrief 包含较早/近期消息的受限摘录与当前约束，不是无限容量的语义记忆，也不宣称实现了 LLM 滚动总结。

Redis 是短期缓存，持久化上下文可从 MySQL 或 SQLite 回填。历史归档和模型本轮的裁剪上下文不是同一份数据；旧天气、路况等不能因保存在历史中就当作当前事实。当前尚未实现历史记录自动保留期清理。

## 首次输入为何曾经答错

最早一轮可能离开历史窗口或超过上下文 TTL。此时让模型猜，即使数据库仍有原文，也可能答错。

明确的首次输入查询现在走独立只读路径：

```text
识别“第一次输入是什么”类元问题
  → 按当前用户和会话查询根任务
  → ORDER BY created_at, id LIMIT 1
  → 返回 query 原文
  → Trace: conversation.history_retrieved + source_task_id
```

这条路径不受模型窗口和近期上下文 TTL 限制，因为用户明确请求读取历史档案，而不是要求沿用旧业务事实。新会话不读取其他会话的首条消息；记录不存在时不编造。当前支持的是首次输入原文，不是任意跨会话全文搜索。

## 临时执行引用

`conversation_references` 保存已完成任务的紧凑证据：领域、必要槽位、选中候选的 ID/名称/坐标与来源任务，不保存整张地图几何。按用户及会话隔离，仅读取源任务仍为 completed 的记录。

天气追问复用城市，但重新调用天气工具。地点追问复用已选坐标，但路线距离、用时和轨迹仍需重新获取。非天气引用采用候选有效期与工具回执期限中更早的一项；过期不复用。多个不同地点同时有效时，“导航过去”要求重新明确目的地，不根据最后完成的并行分支猜目标。

临时地点引用不会跨会话继承，也不会把目的地改写为当前 GPS 位置。候选引用只帮助读操作，不代替写入授权。引用持久化后重启仍可读取，但每次重新检查期限和源任务状态。

## 长期偏好

偏好按 user_id + key 存储，可跨会话读取、覆盖和删除。页面编辑器和明确的“记住：键=值”命令会真实写入；普通“我喜欢……”不会静默永久保存。

偏好现在同时传给闲聊、意图识别和复合任务规划，而不只传给最终答复。当前明确要求优先于偏好；偏好是数据，不是系统指令或授权依据。单轮最多注入最近 20 项、合计 4000 字符，界面仍可列出完整偏好。

不自动保存敏感推断。项目尚未实现完整隐私导出、自动遗忘或多租户 IAM；本地演示身份不可直接公开到互联网。

## 恢复与去重

主输入框只在唯一有效候选或已知城市缺参匹配时恢复，复用现有生命周期锁、过期校验和恢复预算。多个任务均可匹配时不猜测，确认/拒绝写操作仍使用专门卡片。

`conversation_inputs` 保存请求标识、会话归属、输入和恢复回执。同 ID 重复提交返回同一结果，用于其他内容或创建另一任务时拒绝。这不等于远端副作用恰好执行一次。

## 验证

新增 9 项受控测试覆盖跨轮天气、主输入框城市补充/候选选择、重复请求、选中坐标复用、多个候选歧义、过期拒绝、偏好传入模型/删除、重启隔离与首次输入越过窗口/TTL 后仍原样返回。受控测试不等于真实模型准确率。
