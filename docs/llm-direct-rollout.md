# 自由文本直接交给DeepSeek：启用与失败案例

日期：2026-10-29。用户在DeepSeek基准对比后批准采用`INPUT_EVENT_PROVIDER=llm_direct`，不启用Jev纯回复过滤。基础模型、思考参数、领域Jev和任务数量门控保持不变。

## 当前入口

```text
live主输入框／卡片内手工输入
  → DeepSeek输出InputDecision
  → 宿主校验任务归属、原文覆盖、候选有效期和权限
  → 恢复旧任务／创建新任务／取消／继续澄清

结构化候选按钮、审批确认／拒绝、取消按钮
  → 原宿主协议，不调用文本事件LLM或事件Jev
```

纯回复例如“无锡校区吧”和复合回复“无锡校区吧，顺便查下明天无锡天气”均先交事件LLM；后一种返回旧任务回复与新需求原文两个片段。直接LLM不等于直接执行，仍会拒绝错误任务ID、丢失后半句、过期候选及用“好的”替代写操作授权。

配置模板与本地`.env`显式选择`llm_direct`；裸Settings保留`llm`兼容旧部署。`resolve_input`在direct策略下也显式忽略残留/注入的事件router，避免错误配置叠加Jev。demo路径仍离线，真实LLM异常返回503及重试/使用卡片提示，不猜测恢复、不静默降级到规则执行。

## 为什么采用

此前冻结36条事件：直接DeepSeek与Jev过滤均34/36；纯回复与复合回复各12/12，边界各10/12。事件P50为0.852→1.216秒，完整5会话P50为5.452→7.595秒（A→B）。所以采用直接DeepSeek，**不是证明比原来的零模型规则更快，也不是证明边界100%正确**。

两条边界失败是取消任务和带引号的词义提问被过度澄清，两个策略都失败；本次不调提示词或修改标注来抬高旧指标。具体结果仍见[冻结报告](../evaluations/jev/2026-10-29-deepseek/v1/README.md)。

## 全链路12例中失败的两例

### 1. 天气结果依赖保存：multi_completion-04

输入：“查无锡今天天气，然后把查到的完整天气结果保存到行程，标题为无锡天气记录”。

期望：`t1`查询天气，`t2`等待`t1`成功并把真实回执绑定到行程`details`，经用户确认后写入。实际两组均在全局规划第一次输出及一次格式修复后失败，未创建可执行子任务，也未调用天气或保存工具；耗时A=2.395秒、B=2.803秒，不是成功时延。

原记录保留的JSON包含错误绑定：

```json
"bind_slots": {"result": "t1.result"}
```

左边是**后继任务接收字段**，不是前置结果的名字。`SlotValues`允许`details`而不允许`result`，因此GoalPlan的语义校验拒绝该计划。右边`t1.result`是合法的前置工具回执路径。正确的绑定应是：

```json
"depends_on": ["t1"],
"bind_slots": {"details": "t1.result"}
```

### 2. 三分支并行＋一个依赖保存：jev-four-goals

输入：“查无锡今天的天气，同时搜索周杰伦的歌曲，同时查看我的行程清单，天气查询成功后把完整天气结果保存到行程，标题为无锡天气记录。前三项可以并行，保存只依赖天气结果。”

期望：天气、音乐、行程列表三个任务并行，保存任务只依赖天气。实际两组也在GoalPlan校验及一次修复后失败，尚未进入并发调度或工具调用；A=2.184秒、B=2.598秒。

原记录的异常信息仅保留300字符，四任务JSON被截断，不能仅从原片段确认具体字段。本次另做**不执行工具的独立诊断调用**，完整输出再次出现`"bind_slots":{"result":"t1.result"}`，并返回“槽位绑定目标不属于允许的业务字段”。这是新诊断复现，不冒充恢复出了原来被截断的响应。

[两个新诊断的完整输出、校验错误及用量](../evaluations/jev/2026-10-29-deepseek/v1/diagnostics/planning-20261029.json)。诊断使用空摘要及新时间，不混入旧12例的准确率、耗时或Token。

### 共同问题与改进边界

- 不是高德请求失败或音乐接口超时，也不是Jev领域选错：计划尚未通过校验，业务工具未启动。
- `bind_slots`在JSON Schema中是泛化字典，合法目标字段限制主要在Pydantic后置校验中；模型容易把右侧结果名复制为左侧目标字段。
- 目前遇到包装后的`OutputParserException`，修复提示仅告诉模型“不符合Schema”，没有明确指出非法目标`result`，因此一次重试仍重复原错误。
- 后续应将合法绑定目标写入可验证的模型契约，并把脱敏字段级诊断用于有界修复，再回归依赖、循环、引用和实际保存证据。不能直接取消校验，也不能把任意未知键静默改为`details`。

本次仅切换事件解释策略并补充定位证据，**没有修改规划绑定逻辑，也没有把10/12改写为12/12**。

## 验证与回滚

新增受控测试证明：direct文本绕过事件规则及残留Jev、纯回复/复合片段完整、模型失败不猜测恢复；已有测试继续核对结构化选择及审批按钮不调用文本解释器。真实五会话覆盖文本选择、缺城市、两种恢复＋新需求及卡片对照。

切换后独立重跑5会话全部完成，记录9次事件DeepSeek、0次事件Jev（初始新请求也需要事件解释；卡片点击本身不新增事件模型调用）。这是单臂回归，不与旧配对混算速度。[脱敏结果与配置](../evaluations/jev/2026-10-29-deepseek/v1/rollout/llm-direct/summary.json)。本机容器已重建，真实认证HTTP/SSE的天气和歌手介绍两例再次completed；验收记录保存在本地`data/llm-direct-http-smoke-20261029.json`。

待发布隔离快照回归**790通过、2跳过**，JUnit保存在本机`data/llm-direct-snapshot-tests-20261029.xml`。原事件规则测试固定旧`llm`策略，避免私有部署配置改变测试语义；direct策略用独立测试显式覆盖。受控回归通过不等于模型准确率100%。
