1. **真实模型组件测试**：DeepSeek 实际选择领域动作和工具，并提取工具入参字段。

3. **工程受控回归**：使用 HTTP Mock、队列故障注入和测试 dispatcher，验证重试、权限、幂等、依赖、并发和结果边界。

## 指标口径

- **工具选择准确率**：领域、action 和 `tool_name` 同时匹配标注；不能只看领域正确。
- **工具参数准确率**：已标注工具字段逐字段比较；同时报告整组全对率，防止字段平均值掩盖关键字段错误。
- **工具调用成功率**：真实 MCP 请求拿到结构化成功回执且关键证据存在；不是只看 HTTP 200。
- **错误重试正确率**：可恢复网络/超时/429/5xx 等按策略重试；参数错误、权限错误、幂等冲突和写入结果未知不能自动重试。
- **不可恢复错误处理率**：停止继续执行、进入失败或 Dead Letter，并给出可解释状态；不能用“重试后成功”替代停止策略。
- **工具结果解析准确率**：检查返回对象类型、成功标志、关键字段、错误码和候选 ID；不把缺字段结果补成成功。
- **工具结果绑定准确率**：后置任务只能读取前置任务真实 Checkpoint 回执，且字段类型、来源任务和路径均正确。
- **执行顺序正确率**：有依赖时后置任务的 `started` 必须晚于前置 `completed`；前置失败时后置不得入队。
- **并行执行正确率**：独立分支必须出现重叠执行证据，同时在 Trace/DAG 中没有虚假的依赖边。

## 边界

1. 真实 MCP 的 28/28 是当前凭证、网络和服务状态下的联调结果，不等同于长期 SLA。
2. 模型工具选择只有 30 条；修复后 30/30 仅说明冻结回归集通过，不能宣称线上工具选择准确率为 100%。
3. 受控回归证明工程协议，不代表远端服务“恰好执行一次”；写操作结果未知时仍必须人工核对账本。
4. 结果解析测试验证结构和证据，不评价天气预测正确性、音乐版权播放或商家实时营业状态。
